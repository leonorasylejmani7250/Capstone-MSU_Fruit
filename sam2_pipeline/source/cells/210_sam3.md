## Appendix B · Scoring SAM 3.1 (or any model that lives in another program)
SAM 3.1 needs Meta's `sam3` package (Python 3.12+, PyTorch 2.7+, a CUDA 12.6+ GPU) and Hugging Face access to its gated weights (`facebook/sam3.1`). The safe way to compare it is to keep it in its own environment and let it **write its masks into this project's `predictions/` folder**. Then it is scored here like everything else.

**In the team repository this is already written:** `sam3_pipeline/run_sam3.py clips` (its README says how to install and run it) writes `predictions/sam3_text/<clip>/<frame>.png` for every labelled val clip, and the `SAM 3.1 · text 'grape cluster'` entry in `configs/lineup.yaml` scores that folder as soon as it exists. On the HPCC, `hpcc/run_all.sh` at the repository root runs it together with the fine-tuning jobs.

**By hand, from any program**, the contract is: one PNG per frame, named like the frames (`00000.png` for `00000.jpg`), pixel value = object number (the same number for the same cluster from frame to frame), 0 = background. With Meta's `sam3` package it looks like this:

```python
import json, numpy as np
from pathlib import Path
from PIL import Image
from sam3.model_builder import build_sam3_multiplex_video_predictor     # SAM 3.1; SAM 3: build_sam3_video_predictor

ROOT = Path("/content/drive/MyDrive/msu_fruit_sam2")     # the same project folder this notebook uses
TEXT = "grape cluster"
OUT  = ROOT / "predictions" / "sam3_text"
predictor = build_sam3_multiplex_video_predictor(max_num_objects=64)    # Meta's default of 16 objects is too few for a vine row

clips = json.loads((ROOT / "dataset" / "clips.json").read_text())
for clip, info in clips.items():
    if info.get("split") != "val" or info.get("status") != "done":
        continue
    frames = sorted((ROOT / "dataset" / "JPEGImages" / clip).glob("*.jpg"))
    w, h = Image.open(frames[0]).size
    sid = predictor.handle_request(dict(type="start_session", resource_path=str(frames[0].parent)))["session_id"]
    predictor.handle_request(dict(type="add_prompt", session_id=sid, frame_index=0, text=TEXT))
    out = np.zeros((len(frames), h, w), np.uint8)
    for r in predictor.handle_stream_request(dict(type="propagate_in_video", session_id=sid, propagation_direction="forward")):
        for k, m in zip(r["outputs"]["out_obj_ids"].tolist(), r["outputs"]["out_binary_masks"]):
            assert m.shape == (h, w), f"mask is {m.shape}, frame is {(h, w)}"
            out[r["frame_index"]][np.asarray(m, bool)] = min(int(k) + 1, 255)   # 0 stays background
    predictor.handle_request(dict(type="close_session", session_id=sid))
    (OUT / clip).mkdir(parents=True, exist_ok=True)
    for f, m in zip(frames, out):
        Image.fromarray(m).save(OUT / clip / (f.stem + ".png"))                 # pixel value = object id
```

**Back here**, run:

```python
benchmark({"SAM 3.1 · text 'grape cluster'": FromFolder(PRED / "sam3_text", tracks=True)})
```

If `sam3` is installed in *this* runtime instead, `benchmark({"SAM 3.1": SAM3Text("grape cluster")})` calls it directly (or `type: sam3` in a lineup file). Both follow the request/response format of Meta's `sam3` code as documented for SAM 3.1 (March 2026: `build_sam3_multiplex_video_predictor`, `start_session`, `add_prompt`, `propagate_in_video`) but were **not run** while this pipeline was tested, because the weights are gated. Expect to fix a detail or two; `run_sam3.py` falls back to a temporary video file if `start_session` refuses a folder of frames.
